# AutoFlash

Приложение для мастерской: подключается к автомобилю через OBD-адаптер (Bluetooth LE или Wi-Fi), само определяет авто, блоки управления и версии прошивок, показывает ошибки и живые данные, подбирает доработки из каталога и ведёт клиентов и заказы.

## Что уже работает

| Возможность | Состояние |
|---|---|
| Подключение: Bluetooth LE, Wi-Fi (TCP), Web Bluetooth (Chrome), демо-режим | Код написан; проверен только в демо-режиме и сборкой Android |
| Определение авто: VIN по OBD и UDS, производитель/страна/год офлайн, модель и двигатель через NHTSA | Проверено на симуляторе |
| Опрос блоков по стандартным адресам CAN (7E0…7E7): номера ПО, HW, поставщик, серийник, дата | Проверено на симуляторе |
| Calibration ID и CVN по OBD-II (режим 09) | Проверено на симуляторе |
| Ошибки (сохранённые, ожидающие, постоянные), сброс с подтверждением | Проверено на симуляторе |
| Живые данные (обороты, температура, нагрузка, MAP, напряжение и др.) | Проверено на симуляторе |

## Чего приложение НЕ делает и почему

- **Не пишет прошивку в блок через ELM327.** Для записи нужен J2534-интерфейс или профильный программатор и драйвер конкретного семейства блоков (протокол загрузчика, SecurityAccess, контрольные суммы). Через дешёвый адаптер обрыв записи «кирпичит» блок. Поэтому приложение отказывается писать через ELM327, а вся «обвязка» вокруг записи уже готова (`src/core/flash.ts`): подключить реальный интерфейс = реализовать `FlashProvider`.
- **Не содержит файлов прошивок.** Каталог пока демонстрационный. Файлы должны быть ваши или от партнёра, с эталонной SHA-256 и совместимостью по номеру ПО.
- **Не включает позиции, отключающие системы очистки выхлопа.**
- Нет общего облака: данные одной мастерской на одном компьютере (копии есть). Общий доступ сотрудникам требует сервера и аккаунта хостинга.
- Нет подписи установщика: Windows может показать предупреждение SmartScreen (подпись требует платного сертификата).
- J2534-драйвер не написан: нужен ваш конкретный интерфейс (DLL производителя) для проверки.
- Протокол проверен на программном симуляторе, а не на живых автомобилях. Реальные адаптеры и ЭБУ отличаются, поэтому первая задача при выходе на машины: прогнать приложение на 5–10 разных авто и разобрать журнал обмена (Ещё → Журнал).

## Настольное приложение (Windows)

Настоящее приложение `AutoFlash.exe` на Electron: тот же интерфейс, но с возможностями ПК.

- Bluetooth LE-адаптеры, COM-порты (USB-кабели и Bluetooth-адаптеры, спаренные в Windows), Wi-Fi адаптеры по TCP.
- Выбор устройства в окне приложения; скорость COM-порта подбирается автоматически.

```bash
npm run desktop:build                                   # сборка в desktop/out/AutoFlash-win32-x64
powershell -ExecutionPolicy Bypass -File desktop/install.ps1   # установка + ярлык на рабочем столе
npm run sim-server                                      # виртуальный Wi-Fi адаптер 127.0.0.1:35000 для проверки без железа
AutoFlash.exe --selftest=<папка>                        # самопроверка: подключение → скан → скриншоты и report.json
```

## Запуск

```bash
npm install
npm test            # автотесты ядра (протокол, VIN, каталог, прошивка)
npx expo start --web   # быстрый просмотр в браузере (демо и Web Bluetooth)
```

Для Bluetooth и Wi-Fi на телефоне нужна dev-сборка (Expo Go не содержит этих модулей):

```bash
npx expo install expo-dev-client
npx eas build --profile development --platform android
```

## Устройство

- `src/core/` — вся логика без UI: драйвер ELM327, OBD-II, UDS, VIN, сканер, каталог, прошивка, симулятор автомобиля.
- `src/transport/` — каналы связи (BLE, Wi-Fi, Web Bluetooth).
- `src/storage/` — клиенты, авто, заказы.
- `src/app/` — экраны (Expo Router).
- `tests/` — автотесты на симуляторе.
